# Проход качества Vault (ночной бриф)

Это рабочее задание для длинной автономной сессии (5–7 часов) и для всех агентов, которые в ней участвуют.
Вопросов пользователю не задаём — решения принимаем сами по CLAUDE.md и `docs/design-system.md`, спорное
фиксируем в отчёте.

## Цель

Довести Vault до состояния «всё работает правильно и выглядит продуманно» на каждом экране, в каждой карточке,
форме, переходе и во всём флоу — включая расширение Chrome. Код при этом организован по SOLID (без FSD),
повторяющееся вынесено в общие части, всё по дизайн-системе.

## 1. Архитектура (SOLID по-реактовски, без FSD)

- **S.** Компонент делает одно. Логика данных — в хуках (`useApi`, `useApiMutation`, `useAutosave`, свои
  `useXxx`), разметка — в компонентах. Файл больше ~400 строк или компонент больше ~150 строк — кандидат
  на разбиение по смыслу (секции, строки, диалоги, хуки).
- **O.** Сквозные фичи — через реестры (`EntityRegistry`, `IMPORT_DEFS`, `ENTITY_META`, shortcuts). Новый
  модуль не требует правок сквозного кода.
- **L.** Модули расширяют `SoftRepository`, не ломая базовое поведение.
- **I.** Узкие API на модуль в `src/shared/api.ts`.
- **D.** renderer и main зависят от контракта `src/shared`; зависимости main — через конструктор
  (`container.ts`).
- **Переиспользование.** Одинаковый кусок UI или логики в двух местах → в `components/common` /
  `lib` / `hooks` (renderer), `core` / `services` (main), `shared` (оба). Дубли не плодим.
- Никаких «AI-артефактов» в коде: комментариев-пересказов («// Here we set the state»), мёртвого кода,
  неиспользуемых экспортов, `console.log`, закомментированных блоков, TODO без смысла. Комментарий объясняет
  *почему*, а не *что*.

## 2. Дизайн-система

Всё по `docs/design-system.md`: только shadcn-компоненты, роли шрифтов (`text-meta … text-display`,
никаких `text-[Npx]`/`text-xl`), токены цвета, один яркий акцент на экран, радиусы по иерархии, общие
`tile`/`--tile-hover`, `MoneyValue`/`MoneyLines`, `EmptyState`, `FormDialog`, `StatTile`, `IconAction`.
Новое правило — сначала в `design-system.md`, потом в код.

**AI-артефакты в дизайне — убираем, новых не делаем:**
- стрелки «→» в тексте кнопок без смысла перехода; декоративные градиенты; эмодзи в интерфейсе;
- ALL-CAPS и разрядка в подписях; «надзаголовки» над каждым блоком; номера 01/02/03 там, где нет
  последовательности;
- цепочки «A · B · C · D» там, где хватит одного-двух фактов; одинаковые карточки с одинаковой тенью
  для разнородного контента;
- заглушки и «рыба»: lorem, «Описание тут», выдуманные числа, плейсхолдер, который выглядит как значение;
- пустые декоративные иконки, которые ничего не обозначают; лишние подсказки, повторяющие очевидное.

## 3. Состояния — проверяем КАЖДЫЙ экран и КАЖДУЮ карточку

| Состояние | Что должно быть |
|---|---|
| Загрузка | скелетон формы реального контента, без прыжков при подмене |
| Пусто (нет записей) | `EmptyState`: что здесь будет + одно действие, чтобы начать |
| Мало контента (только обязательные поля) | читается аккуратно, нет пустых рамок; подсказка, что заполнить |
| Обычно | вся нужная информация видна сразу, второстепенное — тише |
| Много (500 символов, слово без пробелов, суммы 100 млн, сотни записей) | ничего не вылезает и не режется посреди слова: перенос или «…» + полный текст по наведению/в карточке |
| Ошибка загрузки | понятный текст + «Повторити» (глобально через QueryCache) |
| Просмотр / правка | «Редагувати» → поля; «Зберегти»/«Скасувати»; Esc спрашивает |
| Только что создано | сразу правка, фокус в первом поле, «Скасувати» удаляет |

## 4. Формы и поля

- Лимиты из схем (`limitsOf`, `rangesOf`, `MAX`), ввести больше нельзя; числа с min/max; даты с `min`.
- Ошибка — у поля, по-украински, говорит как исправить. Подпись поля всегда есть; плейсхолдер — пример,
  не замена подписи.
- Обязательные поля отмечены поведением: кнопка неактивна, пока форма невалидна (с объяснением).
- Enter отправляет короткие формы, Esc закрывает; фокус в первом поле; двойной клик не создаёт дубль;
  на время запроса — pending; успех/ошибка — короткий тост по-украински.
- Ссылки нормализуются (`normalizeUrl`), открываются через `openUrl`; email проверяется.

## 5. Переходы и движение

- Тихие анимации (`design-system.md → Движение`): ничего не прыгает, нет мигания пустоты между
  скелетоном и контентом, панели открываются/закрываются плавно.
- Скролл и фокус: после закрытия диалога фокус возвращается; после создания записи она видна и выделена;
  переход по ссылке открывает нужную запись.

## 6. Флоу (сквозные сценарии)

Создать → заполнить → сохранить → найти (поиск, фильтры, метки) → изменить → «Скасувати» → удалить →
восстановить из корзины → удалить навсегда. Связи, закрепы/избранное, импорт JSON, экспорт и бекап,
таймер (окно и трей), календарь и напоминания, конвертации (идея → дошка, відгук → контракт/шаблон),
горячие клавиши (`N`, `E`, `Esc`, `/`, `Ctrl+K`, `Ctrl+/`), обновления.

## 7. Расширение Chrome

Попап каждого типа (дизайн, закладка, бібліотека, компонент, вакансія): нет ключа, нет связи, длинный
заголовок, без выделения, с выделением, после сохранения, «Зберегти ще», выделение области; страница
настроек; `capture-server` (валидация, лимиты, ошибки). Тот же уровень UI, что в приложении.

## 8. Процесс

1. **Снимки:** `npm run build`, затем `node scripts/snap-all.mjs <dir>` (все экраны, детали записей —
   обычная/пустая/огромная, формы создания, режим правки, пустая база; тёмная и светлая темы) и
   `node scripts/snap-extension.mjs <dir>`. Плюс `scripts/audit-overflow.mjs` (переполнения на экстремальных данных) и
   `audit-empty.mjs` (пустая база, зависшие скелетоны).
2. **Ревью** по зонам параллельно (только чтение): скриншоты + код → находки. Скилы:
   `ui-design-review:ui-review`, `design:accessibility-review`, `design:ux-copy`,
   `engineering:architecture` для структуры кода.
3. **Проверка находок** скептиком (ложные/вкусовые без пользы — отбрасываем).
4. **Правка** по зонам параллельно; зоны не пересекаются по файлам. Скилы: `ui-design-review:ui-polish`,
   `frontend-design` (для заметно переделываемых частей), `simplify`.
5. **Проверка:** `npm run typecheck`, `npm test`, `npm run build`, `npm run test:e2e`, повтор снимков.
   Коммиты по зонам, Conventional Commits.
6. Повторять круги, пока ревью не перестанет находить существенное. Гайд и `design-system.md` — в конце
   каждого круга. Релиз беты — после стабильного круга.

**Правила параллельной работы:** правишь только файлы своей зоны; общие файлы (`components/common/*`,
`components/ui/*`, `styles/globals.css`, `lib/*`, `hooks/*`, `docs/*`, `guide-page.tsx`, `CLAUDE.md`)
меняет только зона «Оболочка» или оркестратор — остальные присылают запрос в отчёте или создают НОВЫЙ
файл в `components/common`; `npm run build`/`test:e2e`/коммиты — только оркестратор; typecheck-ошибки
чужих файлов игнорируешь.

## 9. Готово, когда

- typecheck, unit и e2e зелёные; три аудита без находок; снимки всех состояний выглядят продуманно в обеих
  темах; расширение на том же уровне;
- нет дублей, которые стоило вынести; большие файлы разбиты по смыслу;
- `design-system.md`, гайд и CLAUDE.md отражают итог; выпущена бета.
