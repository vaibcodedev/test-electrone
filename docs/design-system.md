# Система стилей Vault

Единые правила внешнего вида. Всё собирается из shadcn (`src/renderer/src/components/ui`), стиль задают токены в `styles/globals.css` и варианты `cva` внутри `components/ui`. Новый экран не придумывает свои размеры, цвета и кнопки, а берёт роли отсюда. Если нужной роли нет, сначала добавь её сюда и в токены, потом используй.

## 1. Принципы

1. **Сначала читаемость, потом декор.** Заголовок карточки должен читаться с первого взгляда: он не бывает серым и мелким.
2. **Один яркий акцент на экран.** Лайм (`lime`) получает одно главное действие или одна «герой»-плитка. Остальное нейтрально.
3. **Иерархию задают слои и радиус, а не рамки.** Рамка окна `frame`, затем панель `card`, плитка `surface`, а элемент внутри плитки снова `card`.
4. **Что кликается, то выглядит кликабельным.** Кнопка похожа на кнопку, ссылка на ссылку. Серый текст без фона не бывает кнопкой.
5. **Тёмная тема — это не перекраска.** Оттенки проверяются в обеих темах (`npm run snap`, `SNAP_THEME=dark`).

## 2. Цвета (токены)

| Токен | Роль | Светлая | Тёмная |
|---|---|---|---|
| `frame` / `background` | рамка окна, фон под панелями | `#d8dcd2` | `#0e0f11` |
| `card` | основная панель страницы; элементы внутри плиток | `#f7f8f4` | `#18191c` |
| `surface` | плитки и карточки на панели (`Card`) | `#eceee7` | `#232428` |
| `foreground` | основной текст | `#14160f` | `#f3f4f1` |
| `muted-foreground` | вторичный текст (описания, мета) | `#5d6255` | `#b2b4ba` |
| `accent` | hover нейтральных элементов | `#e4e7de` | `#2d2e33` |
| `lime` / `lime-foreground` | единственный яркий акцент | `#d4f542` | `#d8f74a` |
| `ink` / `ink-foreground` | инвертированная «герой»-плитка, активный пункт | чёрная | светлая |
| `ink-muted`, `ink-accent` | вторичный текст и акцент **на** ink | `#a7ad9f`, лайм | `#55585f`, олива |
| `success` / `warn` / `info` / `destructive` | статусы (только в бейджах, иконках, тексте статуса) | — | — |
| `chart-1…5`, `chart-bar` | графики, проверены валидатором dataviz (≥3:1 к `surface`) | — | — |

Правила:
- Никаких hex-цветов в компонентах. Исключение — пользовательские цвета (метки, площадки), они приходят из данных.
- Текст на `ink` берётся только из `ink-foreground` / `ink-muted` / `ink-accent`.
- Новый цвет графика сначала прогоняется через скил `dataviz` (валидатор контраста и CVD).

## 3. Типографика

Размеры — только именованные роли (`--text-*` в `@theme`). Произвольные `text-[13px]` запрещены. Межстрочный интервал задаётся отдельно (`leading-*`), токены его не навязывают.

| Класс | Размер | Где | Вес и цвет |
|---|---|---|---|
| `text-display` | 52px | герой дашборда | `font-display` |
| `text-title` | 36px | заголовок страницы (`PageHeader`) | `font-display` |
| `text-stat` | 34px | число в плитке статистики | `font-display tabular-nums` |
| `text-stat-sm` | 22px | маленькое число, итог в карточке | `font-display tabular-nums` |
| `text-lead` | 15px | выделенный заголовок внутри панели | `font-medium` |
| `text-body` | 13.5px | основной текст, заголовки строк, кнопки | `font-normal`/`font-medium` |
| `text-caption` | 12.5px | описания, подсказки, вторая строка | `text-muted-foreground` |
| `text-meta` | 11.5px | время, счётчики, легенды, бейджи | `text-muted-foreground` |

Роли заголовков:
- **Заголовок карточки** — `CardTitle`: `text-body font-semibold text-foreground`. Не перекрашивать в серый.
- **Подпись секции** (над группой полей, «Связи», «Файлы») — `SectionLabel` / `h3.text-caption.font-semibold.text-muted-foreground`.
- **Описание карточки** — `CardDescription`: `text-sm text-muted-foreground`, одна-две строки.
- **Подпись плитки статистики** — `text-body font-medium text-muted-foreground` над числом.
- Крупные заголовки с числами (итоги недели): числа и слова склеены неразрывными пробелами, чтобы «1» не отрывалось от «собеседование».

Если добавляешь роль, зарегистрируй её ещё и в `lib/utils.ts` (`extendTailwindMerge` → `theme.text`). Иначе `cn('text-x', 'text-muted-foreground')` примет размер за цвет и выкинет один из классов.

## 4. Радиус, отступы, слои

- Радиус задаёт иерархию: окно 28 (`rounded-3xl`), панель 24, плитка 18–24 (`Card` = `rounded-3xl`), контрол 12, чип и кнопка — `rounded-full`.
- Отступы внутри `Card` — `px-5 py-5`. Между плитками сетки — `gap-3`. Между строками списка — `gap-1.5`.
- Элемент внутри плитки (строка списка, мини-карточка) имеет фон `bg-card`, `rounded-2xl`, отступы `px-4 py-3` или `p-2.5` для компактных строк.
- Текст никогда не прижимается к скруглённому углу: в плитках с радиусом ≥18 внутренний отступ ≥8px.

## 5. Кнопки и ссылки

| Вариант `Button` | Когда | Пример |
|---|---|---|
| `lime` | одно главное действие экрана | «Новая доска», «Вакансии» |
| `default` | `primary`: в светлой теме чёрная, **в тёмной лаймовая** — поэтому только для главного действия формы/диалога, никогда в повторяющихся карточках | «Сохранить» в форме |
| `soft` | второстепенные действия в шапке страницы, на фоне `card` | «Площадки», «Импорт из папки» |
| `subtle` | **переход из карточки** в другой раздел, на фоне `surface` | «Календарь», «Все библиотеки», «Изменить время» |
| `ghost` | иконки и тулбары; hover — тонировка `foreground/7%` | ✕, ⋯, «Открыть» иконкой |
| `outline` | альтернатива soft там, где фон совпадает | «Стоп dev» |
| `link` | ссылка внутри текста; без отступов, тонкое подчёркивание | путь к репозиторию, имя проекта |
| `destructive` | только в подтверждении удаления | «Удалить навсегда» |

Опасное действие — `destructive` с иконкой, никогда не lime; отмена — `soft`, фокус по умолчанию на отмене (`Confirm`, `tone`).

Правила:
- Действия внутри повторяющихся карточек (проекты, записи) — только нейтральные: `subtle`, сплит-кнопка = `ButtonGroup` из двух `subtle` с `ButtonGroupSeparator`. Цвет — только у иконки (▶ `text-success`).
- Навигация из карточки — `subtle size="xs"`. Если действие стоит под числом или в строке — добавь `<ArrowRight />`.
- `link` всегда стоит вровень с текстом: размер не добавляет `px`/`h` (это делает `compoundVariants` в `button.tsx`). Не используй `link` для отдельно стоящих действий, для них есть `subtle`.
- Ссылки-заголовки (имя проекта, запись в списке) — `link` с `no-underline hover:underline`.
- Неактивная залитая кнопка (`lime`, `default`) теряет заливку и получает пунктирную рамку: её нельзя спутать с соседней `soft` («Отмена»). Рядом с ней должно быть видно, *почему* она неактивна (ошибка у поля).
- `ghost`-кнопка в начале строки или футера (например, «В корзину» слева в диалоге) стоит с `-ml-3`, чтобы иконка была на одной линии с полями; опасное действие — `text-muted-foreground hover:text-destructive`.
- У иконочной кнопки обязателен `aria-label` и `Tooltip`.

### Переключатели

- Полоса вкладок и сегментов — по ширине содержимого (`w-fit`), никогда на всю ширину с пустым хвостом.

- Сегменты (`ToggleGroup variant="segment"`, «VS Code / Cursor») и вкладки: выбранный пункт — приподнятая нейтральная плашка (`card` + тень в светлой, `foreground/12%` в тёмной). Не инверсия и не лайм.
- Фильтр-чипы (`variant="chip"`) — выбранный лаймовый: это фильтр экрана, он и есть акцент.

## 6. Бейджи, метки, статусы

- `Badge`: `soft` — нейтральный счётчик; `success` / `warn` / `info` / `destructive` — статус с тонированным фоном; `ink` — инверсия; `lime` — почти никогда (это акцент экрана).
- Дельты «к прошлой неделе»: рост в хорошую сторону — `success`, иначе `soft` + `text-muted-foreground`, без изменений — `soft` «как прошлая».
- Метки (`TagList`) — чип высотой 20px с собственной тонировкой `foreground/7%` (в активной строке — `ink-foreground/12%`), точка цвета метки и текст. Отступ от мета-строки — `mt-1.5`.
- Тип события и стадия — `Badge` статусного цвета. Не дублируй тип в заголовке строки: если заголовок совпадает с типом, покажи компанию или проект.

## 7. Прогресс

- Только `Progress` из shadcn или `SegmentBar` поверх него.
- `SegmentBar` — один сегмент на элемент (до 8). Пять серых сегментов на четыре карточки — ошибка.
- Чек-листы (≤ 12 пунктов): `SegmentBar states={…}` — сегмент = пункт, заполнен ровно там, где пункт отмечен. Отмеченный пункт — приглушённый текст с галочкой, **без зачёркивания** (зачёркнутый текст тяжело читать); зачёркивание остаётся только для закрытых задач на доске.
- Под шкалой всегда подпись «Готово X из Y»; подпись и время разделены `gap-3`, подпись обрезается (`truncate`), а не слипается.

## 8. Формы

- Подпись → поле: всегда 8px; контролы в строке подписи (переключатель режима, счётчик) не увеличивают её высоту.
- Поля ввода (`Input`, `Textarea`, `InputGroup`, `SelectTrigger`, `DatePicker`) видны на любом фоне: тонкая рамка `border-input` + тонировка `foreground/4%`, ярче при наведении, лаймовое кольцо при фокусе. Не перекрашивать их в цвет подложки — поле не должно сливаться с карточкой и не должно выглядеть кнопкой.
- Поле — `Field` из `components/common/page`: подпись не меняется. Ошибка показывается под контролом через `error` (`FieldError`, `text-caption`, `destructive`) и подсвечивает контрол (`aria-invalid`).
- Ошибки по возможности предотвращаются, а не показываются: у даты окончания `DatePicker min={start}`, а смена начала сдвигает конец на ту же длительность.
- **Ограничения ввода.** Лимит длины каждого поля берётся из zod-схемы (`limitsOf(schema)` из `lib/limits`) и передаётся в `maxLength`: интерфейс останавливает ввод ровно там, где сервер отказал бы. Для длинных полей — `Field count={{ length, max }}`: счётчик появляется после 80% лимита.
- Поля ссылок — `type="url"` + проверка `isLikelyUrl()`; ошибка `URL_ERROR` показывается под полем через `Field error`, не сохраняется мусор.
- Превью и заголовки строк обрезаются с многоточием: у строки `min-w-0` по всей цепочке flex-родителей, у текста `truncate` или `line-clamp-*` (длинные слова переносятся глобально).
- Пустые новые записи не плодятся: кнопка «Создать», когда уже есть нетронутая пустая запись, открывает её.
- `Textarea` растёт с текстом до `60vh`, дальше прокручивается внутри; ширину не меняет: длинное слово без пробелов переносится (`overflow-wrap:anywhere`) и не расширяет диалог. Сетка `DialogContent` — `grid-cols-[minmax(0,1fr)]`.

### Паттерны форм

- **Выбор режима с пояснением** (тип оплаты и т. п.): вертикальный `RadioGroup` — радио + метка (`nowrap`) + однострочная подсказка; выбранная строка `bg-card ring-1 ring-foreground/15`, точка радио — лайм. Никаких цветных заливок карточек.
- **Числа в сетке**: короткие метки, единицы (`$ % ★ шт`) — addon в `InputGroup`, сетка `items-end`, ввод — `NumberInput` (черновик текста, коммит на blur/Enter, границы из `rangesOf`).
- **Данные записи в просмотре**: `dl` «метка → значение» с иконками действий (копировать, открыть).
- **Пустая карточка**: иконка в круге + одна строка + `subtle`-действие, по центру карточки.
- **Плитка статистики** без данных пишет фразу («ще немає контрактів»), не «—».
- **Прогресс** не больше 100%; превышение — словами («переплата 300 $»).
- **Длинные колонки и история**: страницы по 30 / «ще N», история — диапазон с «Показати раніші».

### Импорт из JSON

- Типы импорта — реестр `IMPORT_DEFS` в `shared/domain/import.ts`: схема (из input-схемы модуля, лимиты совпадают с сервером), пример, правила для промта, превью. Массивы принимаются как `[…]` и как `{ "items": […] }`, до 500 записей.
- Сервер — `ImportService` (main): модули регистрируют обработчик на свой тип в `container.ts`, весь payload сначала валидируется (всё или ничего). Новый тип = запись в `IMPORT_DEFS` + `importer.register(...)`.
- Интерфейс — один `ImportDialog` / `ImportButton` (`components/common/import-dialog`): вкладки «Текст» / «Файл» (.json до 2 МБ), «Скопіювати промт для ШІ», «Вставити приклад», превью или понятная ошибка, «Імпортувати N». Кнопка — `soft` с `FileJson` слева от главной лаймовой. Обратная сторона — `CopyJsonButton` («Копіювати як JSON», тот же формат).

### Просмотр и редактирование записи

- Клик по записи открывает её **для просмотра**; «Редагувати» (или `E`) включает редактирование, «Готово» (или `Esc`) возвращает просмотр. Только что созданная запись открывается сразу в редактировании.
- Реализация — `components/common/detail-mode`: `DetailPane` делает это сам; свои редакторы (sheet, страница) — `useRecordMode(id)` + `<RecordMode mode>` вокруг тела + `<EditToggle mode>` в шапке.
- Общие поля сами знают режим: `Input`/`Textarea` становятся текстом, `InlineTitle` — заголовком, `MarkdownField` — отрендеренным текстом, `DatePicker` — датой, `TagPicker` — списком меток, `CodeEditor` — read-only; select/toggle/switch показывают только значение (CSS в `globals.css`, вне слоёв). Пустые поля в просмотре скрываются.
- Кнопки, которые только меняют запись («+ Етап», «+ Доступ», иконки правки строк), помечаются `data-edit-only` и в просмотре скрыты. Быстрые безопасные действия (копировать, открыть ссылку, таймер, сменить статус в шапке) работают всегда.

### Пустые записи (черновики)

- Кнопка «+ Створити» создаёт запись с названием из `DRAFT_TITLES` (`shared/entity-types`). Пока её не меняли и поля содержимого пусты (описание типа: `draft` в `EntityDescriptor`), это черновик.
- Повторное «Створити» при живом черновике открывает его же (сервер, `SoftRepository.insert`). Закрытие пустого черновика удаляет его насовсем (`trash.discardDraft`), без корзины; при старте чистятся черновики старше часа.
- Новый тип с кнопкой создания: добавь название в `DRAFT_TITLES` и `draft: { titleField, contentFields }` в дескриптор.

## 9. Пустые состояния и подсказки

- Пустой список внутри карточки — одна фраза `text-body leading-relaxed text-muted-foreground` о том, как список наполнится. Если есть действие — `subtle`-кнопка рядом.
- Пустая страница — `EmptyState` (shadcn `Empty`): заголовок `text-lead font-medium`, подсказка, кнопка действия.
- Тексты — через скил `design:ux-copy`: глагол в кнопке, без «Нажмите здесь».

## 10. Списки и плитки

- Строка списка — `Item` (`ListItem` в master-detail): заголовок `text-body font-medium`, мета `text-caption`/`text-meta` muted. Активная строка — `ink`.
- Плитка статистики: подпись (`text-body font-medium muted`) → число `text-stat` слева и действие `subtle` справа на одной линии.
- Строка «событие с датой»: слева блок даты `w-16 rounded-xl bg-surface` («завтра» `text-meta` + время `text-lead font-semibold`), дальше заголовок и описание, справа бейдж типа.
- Длинные списки — только `VirtualList` / `VirtualGrid`.
- Превью markdown-описаний в карточках и строках — через `mdPreview()` (`lib/format`), сырые `**` и `#` на экране недопустимы.

## 11. Календарь и тепловые карты

- Сегодня — залитый лаймовый круг `size-6` с числом (`[text-box:trim-both_cap_alphabetic]` для оптического центра), у ячейки тонкая обводка `ring-lime/70`. Без белых «таблеток».
- В ячейке месяца максимум 3 строки. Если событий больше, последняя строка — «ещё N» (`ghost`-кнопка), она открывает `Popover` со всем днём.
- Тепловая карта привычек сгруппирована по неделям (зазор между неделями), клетки `h-7 rounded-[5px]`, над картой короткая сводка в мини-плитках, легенда прижата к низу карточки. Значение каждой клетки — в `Tooltip`.

### Даты и числа

- Даты — только через `lib/format`: `fmtDay` («сьогодні», «завтра», «24 листопада»), `fmtDateTime` («24 листопада о 19:22»), год — только если не текущий. Сокращённые месяцы («лист.») не ставим рядом с запятой.
- Деньги — `fmtMoney`, числа — `tabular-nums` в колонках и статистике.

### Графики

- Цвета — только `chart-1…5` (проверены скилом `dataviz`), новые цвета — через его валидатор.
- Подписи осей — компактные числа (`Intl.NumberFormat('uk-UA', { notation: 'compact' })` + валюта: «50 млн $»), ширина оси — под самую длинную подпись, ничего не обрезается. Точные суммы — в тултипе.

## 12. Системные мелочи

- Скроллбар: 8px, почти невидимый в покое, становится заметнее при наведении на область. Цвета — от `foreground` через `color-mix`.
- `overflow-x-auto` всегда в паре с `overflow-y-hidden` (ленты вкладок, полосы превью): иначе браузер включает и вертикальный скролл из-за 1px фокуса/тени.
- Каждая вертикальная область прокрутки резервирует место под скроллбар (`scrollbar-gutter: stable`, задано глобально по классам `overflow-*-auto`): контент не прыгает, когда скролл появляется.
- Сайдбар прокручивается с мягким затуханием сверху и снизу (`mask-image`).
- Кнопки окна (`titleBarOverlay`) следуют теме, которую показывает renderer (`api.app.setWindowTheme`).
- Курсор `pointer` у всего кликабельного (задано глобально в `globals.css`).
- Фокус — `outline 2px var(--ring)`, его не убирать.

## 13. Движение

Анимация объясняет, что изменилось, а не украшает. Одна кривая `--ease-soft` (мягкий ease-out), короткие длительности, ничего не пружинит. Всё отключается системной настройкой «уменьшить движение».

| Что | Как | Где задано |
|---|---|---|
| Переход между страницами | `animate-page`: 240ms, fade + 4px вверх | обёртка `Outlet` в `AppShell` (ключ — путь) |
| Сетка карточек, обзоры | класс `stagger` на контейнере: дети появляются по очереди (40ms шаг, максимум 10) | `@utility stagger` в `globals.css` |
| Строки списков | после первой загрузки, нового поиска или фильтра — каскад первых 16 строк; при прокрутке без анимации | `VirtualList` / `VirtualGrid` (`useEntering`) |
| Результаты поиска `Ctrl+K` | новые результаты появляются по очереди, оставшиеся не дёргаются | `command-palette.tsx` |
| Панель просмотра справа | `animate-pane`: выезд на 14px + fade | `DetailPane` |
| Раскрытие хабов в сайдбаре | высота `collapsible-down/up` | `sidebar.tsx` |
| Вкладки | содержимое активной вкладки — `animate-page` | `ui/tabs.tsx` |
| Диалоги, поповеры, тултипы | штатные анимации shadcn (`tw-animate-css`) | `components/ui` |

Правила:
- Анимации входа — только `fill-mode: backwards`: после старта элемент свободен, `transform` от dnd-kit, hover и `active:` работают. Поэтому **не ставь `stagger` на сортируемые сетки** (dnd-kit).
- Не анимируй то, что появляется от прокрутки или при каждой перерисовке данных — только реакцию на действие человека.
- Новая анимация — сначала токен `--animate-*` в `@theme`, потом использование.

## 14. Чек-лист нового экрана

1. Есть только одна лаймовая кнопка или плитка.
2. Заголовки карточек — `CardTitle`, ничего серого и мелкого.
3. Размеры шрифта только из ролей (`text-meta…text-display`).
4. Переходы из карточек — `subtle`, ссылки в тексте — `link`, иконки — `ghost` + `Tooltip`.
5. Пустые состояния объясняют, как наполнится экран.
6. Скриншоты в светлой и тёмной теме (`npm run snap`, `SNAP_THEME=dark`), затем скилы `ui-design-review:ui-review` и `design:accessibility-review`.
