# Система стилей Vault

Единые правила внешнего вида. Всё собирается из shadcn (`src/renderer/src/components/ui`), стиль задают токены в `styles/globals.css` и варианты `cva` внутри `components/ui`. Новый экран не придумывает свои размеры, цвета и кнопки, а берёт роли отсюда. Если нужной роли нет, сначала добавь её сюда и в токены, потом используй.

## 1. Принципы

1. **Сначала читаемость, потом декор.** Заголовок карточки должен читаться с первого взгляда: он не бывает серым и мелким.
2. **Один яркий акцент на экран.** Лайм (`lime`) получает одно главное действие или одна «герой»-плитка. Остальное нейтрально.
3. **Иерархию задают слои и радиус, а не рамки.** Рамка окна `frame`, затем панель `card`, плитка `surface`, а элемент внутри плитки снова `card`.
4. **Что кликается, то выглядит кликабельным.** Кнопка похожа на кнопку, ссылка на ссылку. Серый текст без фона не бывает кнопкой.
5. **Тёмная тема — это не перекраска.** Оттенки проверяются в обеих темах (`npm run snap`, `SNAP_THEME=dark`).

| `card` | основная панель страницы; элементы внутри плиток | `#f7f8f4` | `#18191c` |
| `surface` | плитки и карточки на панели (`Card`) | `#eceee7` | `#232428` |
| `foreground` | основной текст | `#14160f` | `#f3f4f1` |
| `muted-foreground` | вторичный текст (описания, мета) | `#5d6255` | `#b2b4ba` |
| `accent` | hover нейтральных элементов | `#e4e7de` | `#2d2e33` |
| `lime` / `lime-foreground` | единственный яркий акцент | `#d4f542` | `#d8f74a` |
| `ink` / `ink-foreground` | инвертированная «герой»-плитка, активный пункт | чёрная | светлая |
| `ink-muted`, `ink-accent` | вторичный текст и акцент **на** ink | `#a7ad9f`, лайм | `#55585f`, олива |
| `success` / `warn` / `info` / `destructive` | статусы (только в бейджах, иконках, тексте статуса) | `#266632` / `#855505` / `#4a55b8` / `#b02a33` | `#6fdc84` / `#ffb547` / `#9aa6ff` / `#ff5c63` |
| `ring` | кольцо фокуса | `#55700a` | `#d4f542` |
| `chart-1…5`, `chart-bar` | графики, проверены валидатором dataviz (≥3:1 к `surface`) | — | — |

Правила:
- Никаких hex-цветов в компонентах. Исключение — пользовательские цвета (метки, площадки), они приходят из данных.
- Текст на `ink` берётся только из `ink-foreground` / `ink-muted` / `ink-accent`.
- **Статусный цвет — это цвет текста:** ≥4.5:1 к `surface` и `card` (и на своём тинте `/12` в бейдже). Яркие оттенки тех же тонов живут только в `chart-*`.
- **Фокус виден всегда:** `--ring` ≥3:1 к `surface`, `card` и лаймовому чипу; кольцо сплошное (`ring-2 ring-ring`, `outline-ring`), не полупрозрачное. На выбранном лаймовом чипе кольцо — `foreground`.
- Новый цвет графика сначала прогоняется через скил `dataviz` (валидатор контраста и CVD).

## 3. Типографика

Размеры — только именованные роли (`--text-*` в `@theme`). Произвольные `text-[13px]` и стандартные `text-xl`/`text-2xl` запрещены — между ролями нет «почти такого же» размера. Межстрочный интервал задаётся отдельно (`leading-*`), токены его не навязывают.

| Класс | Размер | Где | Вес и цвет |
|---|---|---|---|
| `text-display` | 52px | герой дашборда | `font-display` |
| `text-title` | 36px | заголовок страницы (`PageHeader`) | `font-display` |
| `text-stat` | 34px | число в плитке статистики | `font-display tabular-nums` |
| `text-headline` | 28px | заголовок записи и героя, крупное число в карточке | `font-display` |
| `text-stat-sm` | 22px | маленькое число, итог в карточке | `font-display tabular-nums` |
| `text-heading` | 19px | заголовок внутри карточки/панели/диалога, колонки, разделы | `font-display` / `font-semibold` |
| `text-lead` | 15px | выделенный заголовок внутри панели | `font-medium` |
| `text-body` | 13.5px | основной текст, заголовки строк, кнопки | `font-normal`/`font-medium` |
| `text-caption` | 12.5px | описания, подсказки, вторая строка | `text-muted-foreground` |
| `text-meta` | 11.5px | время, счётчики, легенды, бейджи | `text-muted-foreground` |

Роли заголовков:
- **Заголовок карточки** — `CardTitle`: `text-body font-semibold text-foreground`. Не перекрашивать в серый.
- **Подпись секции** (над группой полей, «Связи», «Файлы») — `SectionLabel` / `h3.text-caption.font-semibold.text-muted-foreground`.
- **Описание карточки** — `CardDescription`: `text-caption text-muted-foreground`, одна-две строки.
- Компоненты `components/ui` тоже говорят ролями: пункты меню, поля, вкладки, таблицы — `text-body`; описания, тултипы, `xs`-кнопки и `xs`-тогглы — `text-caption`; бейджи, `Kbd`, шорткаты, легенды графиков — `text-meta`; заголовки диалогов и `Empty` — `text-heading`. Markdown (`.prose-vault`): текст `text-lead`, h1 `text-headline`, h2 `text-heading`, h3 `text-lead font-semibold`, код `text-caption`.
- **Подпись плитки статистики** — `text-body font-medium text-muted-foreground` над числом.
- Крупные заголовки с числами (итоги недели): числа и слова склеены неразрывными пробелами, чтобы «1» не отрывалось от «собеседование».

Если добавляешь роль, зарегистрируй её ещё и в `lib/utils.ts` (`extendTailwindMerge` → `theme.text`). Иначе `cn('text-x', 'text-muted-foreground')` примет размер за цвет и выкинет один из классов.

## 4. Радиус, отступы, слои

- Радиус задаёт иерархию: окно 28 (`rounded-3xl`), панель 24, плитка 18–24 (`Card` = `rounded-3xl`), контрол 12, чип и кнопка — `rounded-full`.
- Отступы внутри `Card` — `px-5 py-5`. Между плитками сетки — `gap-3`. Между строками списка — `gap-1.5`.
- Элемент внутри плитки (строка списка, мини-карточка) имеет фон `bg-card`, `rounded-2xl`, отступы `px-4 py-3` или `p-2.5` для компактных строк.
- Текст никогда не прижимается к скруглённому углу: в плитках с радиусом ≥18 внутренний отступ ≥8px.

- Рамка панели или карточки, которая стоит вплотную к краю контейнера с `overflow:hidden` (панели `Resizable`, списки), — `border`, не `ring-1`: ring рисуется снаружи (box-shadow) и обрезается.

## 5. Кнопки и ссылки

| Вариант `Button` | Когда | Пример |
|---|---|---|
| `lime` | одно главное действие экрана | «Новая доска», «Вакансии» |
| `default` | `primary`: в светлой теме чёрная, **в тёмной лаймовая** — поэтому только для главного действия формы/диалога, никогда в повторяющихся карточках | «Сохранить» в форме |
| `soft` | второстепенные действия в шапке страницы, на фоне `card` | «Площадки», «Импорт из папки» |
| `subtle` | **переход из карточки** в другой раздел, на фоне `surface` | «Календарь», «Все библиотеки», «Изменить время» |
| `ghost` | иконки и тулбары; hover — тонировка `foreground/7%` | ✕, ⋯, «Открыть» иконкой |
| `outline` | альтернатива soft там, где фон совпадает | «Стоп dev» |
| `link` | ссылка внутри текста; без отступов, тонкое подчёркивание | путь к репозиторию, имя проекта |
| `destructive` | только в подтверждении удаления | «Удалить навсегда» |

Опасное действие — `destructive` с иконкой, никогда не lime; отмена — `soft`, фокус по умолчанию на отмене (`Confirm`, `tone`).

Правила:
- Действия внутри повторяющихся карточек (проекты, записи) — только нейтральные: `subtle`, сплит-кнопка = `ButtonGroup` из двух `subtle` с `ButtonGroupSeparator`. Цвет — только у иконки (▶ `text-success`).
- Навигация из карточки — `subtle size="xs"`. Если действие стоит под числом или в строке — добавь `<ArrowRight />`.
- `link` всегда стоит вровень с текстом: размер не добавляет `px`/`h` (это делает `compoundVariants` в `button.tsx`). Не используй `link` для отдельно стоящих действий, для них есть `subtle`.
- Ссылки-заголовки (имя проекта, запись в списке) — `link` с `no-underline hover:underline`.
- Неактивная залитая кнопка (`lime`, `default`) теряет заливку и получает пунктирную рамку: её нельзя спутать с соседней `soft` («Отмена»). Рядом с ней должно быть видно, *почему* она неактивна (ошибка у поля).
- Если причина не в поле (пустой шаблон, текущая неделя), неактивная кнопка стоит внутри `<span tabIndex={0}>` с `Tooltip`-причиной: у `disabled`-кнопки нет событий мыши и фокуса, тултип на ней самой не покажется (во фрилансе — `DisabledHint`).
- Лаймовая кнопка шапки, на которую опирается `N`, не дизейблится из-за пустого поля формы: пустая отправка ставит курсор в поле (иначе `N` её пропустит).
- Главное действие со списком вариантов (Claude «+ Запис», фриланс «Відгук») — `ButtonGroup` из двух `lime`: основная первой (её жмёт `N`), затем `ButtonGroupSeparator` и `DropdownMenu`.
- Иконочное действие с подтверждением (корзина в шапке записи, удаление строки) — `Tooltip > Confirm > TooltipTrigger asChild > Button ghost` (`icon-sm` в шапке, `icon-xs` в строке): тултип и подтверждение висят на одной DOM-кнопке (`TrashButton` в crm).
- Путь «Налаштування → Бекап» в тексте — ссылка на секцию `/settings#<id>` (якоря `you`, `theme`, `system`, `data`, `backup`, `export`, `updates`); в гайде это `SettingsLink`.
- `ghost`-кнопка в начале строки или футера (например, «В корзину» слева в диалоге) стоит с `-ml-3`, чтобы иконка была на одной линии с полями; опасное действие — `text-muted-foreground hover:text-destructive`.
- У иконочной кнопки обязателен `aria-label` и `Tooltip` — для `ghost icon-xs` это одна строка `IconAction label=…`.

### Переключатели

- Полоса вкладок и сегментов — по ширине содержимого (`w-fit`), никогда на всю ширину с пустым хвостом.

- Сегменты (`ToggleGroup variant="segment"`, «VS Code / Cursor») и вкладки: выбранный пункт — приподнятая нейтральная плашка (`card` + тень в светлой, `foreground/12%` в тёмной). Не инверсия и не лайм.
- Фильтр-чипы (`variant="chip"`) — выбранный лаймовый: это фильтр экрана, он и есть акцент. Лаймовая только **основная** группа фильтров экрана; вторая и следующие — `FilterChips tone="neutral"` (выбранный — `foreground/12%`), выбранная метка в `TagFilter` тоже нейтральная (`tone="accent"` — только если это единственный фильтр). Переключатель раздела или вида — `Segmented`, не чипы.
- **Чип-значение поля в записи** (тип, статус закладки, тип дизайна) — нейтральный `foreground/10%` и в просмотре, и в правке: лаймовый чип — это фильтр экрана, а не значение (CSS в `globals.css` по `[data-detail-mode]`).
- Новые значения записи с 2–6 вариантами чипами не делают: в теле записи — `Segmented` (6 вариантов — `size="xs"` + `data-[variant=segment]:flex-wrap` для узкой панели), в узкой колонке `aside` — `Select size="sm" w-full`.
- Ссылки-вкладки (разделы хаба, `FinanceNav`) — `<nav aria-label>` со ссылками; выбранная — `aria-current="page"` и стили `aria-[current=page]:…`. Radix `Tabs` для ссылок без `TabsContent` не используются.

## 6. Бейджи, метки, статусы

- `Badge`: `soft` — нейтральный счётчик; `success` / `warn` / `info` / `destructive` — статус с тонированным фоном; `ink` — инверсия; `lime` — почти никогда (это акцент экрана).
- Дельты «к прошлой неделе»: рост в хорошую сторону — `success`, иначе `soft` + `text-muted-foreground`, без изменений — `soft` «как прошлая».
- Метки (`TagList`) — чип высотой 20px с собственной тонировкой `foreground/7%` (в активной строке — `ink-foreground/12%`), точка цвета метки и текст. Отступ от мета-строки — `mt-1.5`.
- Тип события и стадия — `Badge` статусного цвета. Не дублируй тип в заголовке строки: если заголовок совпадает с типом, покажи компанию или проект.
- Статус «працює / приймає» — `success`, не `lime`.
- **На `ink` статусных цветов нет:** тонированные `warn`/`destructive` на ink в тёмной теме не проходят контраст. Бейдж в активной строке — тонировка `bg-ink-foreground/12 text-ink-foreground`, как у меток (поверх `soft` или `ink`); если у бейджа есть точка, цвет статуса остаётся только у неё. Предупреждение на ink-плитке — текст `text-ink-foreground` с иконкой.
- Бейдж с ограниченной шириной (`max-w-*`): `justify-start min-w-0`, текст во внутреннем `span.truncate`, полный — в `title`.
- Бейдж поверх пользовательского превью (iframe компонента) — на подложке `bg-card`: тонированный статус должен читаться на белом, тёмном и сетчатом фоне.
- Счётчик без подписи (↑/↓ коммитов, иконка-значение) — `Badge` в `Tooltip` с полной фразой через `plural` («3 коміти не відправлено»); бейдж фокусируется (`tabIndex={0}`) и несёт ту же фразу в `aria-label`.

## 7. Прогресс

- Только `Progress` из shadcn или `SegmentBar` поверх него.
- `SegmentBar` — один сегмент на элемент (до 8). Пять серых сегментов на четыре карточки — ошибка.
- Чек-листы (≤ 12 пунктов): `SegmentBar states={…}` — сегмент = пункт, заполнен ровно там, где пункт отмечен. Отмеченный пункт — приглушённый текст с галочкой, **без зачёркивания** (зачёркнутый текст тяжело читать); зачёркивание остаётся только для закрытых задач на доске.
- Под шкалой всегда подпись «Готово X из Y»; подпись и время разделены `gap-3`, подпись обрезается (`truncate`), а не слипается.

## 8. Формы

- Подпись → поле: всегда 8px; контролы в строке подписи (переключатель режима, счётчик) не увеличивают её высоту.
- Поля ввода (`Input`, `Textarea`, `InputGroup`, `SelectTrigger`, `DatePicker`) видны на любом фоне: тонкая рамка `border-input` + тонировка `foreground/4%`, ярче при наведении, лаймовое кольцо при фокусе. Рамка `--input` должна читаться на `--card` (≈20% foreground); не перекрывать её локально `border-transparent`/`bg-surface`.
- Поиск в списках регистронезависим для любого алфавита: в SQL только `ulower()` (своя функция в `db/client`), не `lower()` — тот понимает лишь латиницу. Не перекрашивать их в цвет подложки — поле не должно сливаться с карточкой и не должно выглядеть кнопкой.
- Поле — `Field` из `components/common/page`: подпись не меняется. Ошибка показывается под контролом через `error` (`FieldError`, `text-caption`, `destructive`) и подсвечивает контрол (`aria-invalid`).
- Ошибки по возможности предотвращаются, а не показываются: у даты окончания `DatePicker min={start}`, а смена начала сдвигает конец на ту же длительность.
- **Ограничения ввода.** Лимит длины каждого поля берётся из zod-схемы (`limitsOf(schema)` из `lib/limits`) и передаётся в `maxLength`: интерфейс останавливает ввод ровно там, где сервер отказал бы. Для длинных полей — `Field count={{ length, max }}`: счётчик появляется после 80% лимита.
- Поля ссылок — `type="url"` + проверка `isLikelyUrl()`; ошибка `URL_ERROR` показывается под полем через `Field error`, не сохраняется мусор. Email — так же через `isLikelyEmail()` / `EMAIL_ERROR` (`shared/domain/common`).
- Каждый `MarkdownField` / `AutoMarkdown` / `AutoCode` / `CodeEditor`, который правит поле схемы, получает `maxLength={limitsOf(schema).<поле>}`.
- Пары значений проверяются в UI: конечная дата не раньше начальной (`DatePicker min` + `invalid` + `Field error`), «від» не больше «до». Неверная пара не сохраняется.
- Число вводится только как число: `NumberField` и `NumberInput` принимают один и тот же текст (`acceptNumberText` из `lib/limits`: минус — только если `min < 0`, один разделитель, без ведущих нулей) и разбирают его `parseNumberText`. Недописанное («-», «,») — ошибка «Введіть число, наприклад 4,9», границы — «Від … до …» (числа через `fmtNumber`).
- Число вне диапазона в диалоге блокирует кнопку отправки (`NumberField onValidityChange` + `useInvalidFields`, `components/common/number-field`), а не тихо отбрасывается.
- **Без двойной отправки:** кнопка отправки `disabled` на `isPending`, а `onSubmit` выходит сразу, если запрос уже идёт (Enter не задизейблишь). Поле ввода очищается в `onSuccess`, не до ответа сервера.
- Внутренние записи в main (идея → доска, найм → клиент/проект, событие этапа) обрезают/зажимают значения по лимиту целевой схемы (`fieldMax(schema.shape.<поле>)`), раз репозиторий пишет мимо zod.
- Превью и заголовки строк обрезаются с многоточием: у строки `min-w-0` по всей цепочке flex-родителей, у текста `truncate` или `line-clamp-*` (длинные слова переносятся глобально).
- Пустые новые записи не плодятся: кнопка «Создать», когда уже есть нетронутая пустая запись, открывает её.
- `Textarea` растёт с текстом до `min(50vh, 26rem)`, дальше прокручивается внутри; ширину не меняет: длинное слово без пробелов переносится (`overflow-wrap:anywhere`) и не расширяет диалог. Сетка `DialogContent` — `grid-cols-[minmax(0,1fr)]`.

### Паттерны форм

- **Выбор режима с пояснением** (тип оплаты и т. п.): вертикальный `RadioGroup` — радио + метка (`nowrap`) + однострочная подсказка; выбранная строка `bg-card ring-1 ring-foreground/15`, точка радио — лайм. Никаких цветных заливок карточек.
- **Числа в сетке**: короткие метки, единицы (`$ % ★ шт`) — addon в `InputGroup`, сетка `items-end`, ввод — `NumberInput` (черновик текста, коммит на blur/Enter, границы из `rangesOf`).
- **Данные записи в просмотре**: `dl` «метка → значение» с иконками действий (копировать, открыть).
- **Пустая карточка**: иконка в круге + одна строка + `subtle`-действие, по центру карточки.
- **Плитка статистики** без данных пишет фразу («ще немає контрактів»), не «—». В финансах `MoneyStatTile` требует проп `empty`; пустое значение стат-ячейки в CRM — `EmptyValue` (`modules/crm/parts`: `font-sans text-body` muted, на ink — `text-ink-muted`).
- **Прогресс** не больше 100%; превышение — словами («переплата 300 $»).
- **Длинные колонки и история**: страницы по 30 / «ще N», история — диапазон с «Показати раніші».
- **Поле, ненужное при текущем выборе** (курс при одинаковых валютах), скрывается целиком, а не показывает «1».
- **Форма на другой странице** — параметр `?new=1`: целевая страница открывает форму один раз и убирает параметр (`replace`), состояние меняется во время рендера (`useNewParam` в `modules/freelance`).
- **Сброс формы диалога при открытии** — сравнение с прошлым `open` во время рендера (`if (open !== wasOpen) …`), а не `useEffect` + `setState` с `eslint-disable`: это ловит правило `react-hooks/set-state-in-effect`.

### Импорт из JSON

- Типы импорта — реестр `IMPORT_DEFS` в `shared/domain/import.ts`: схема (из input-схемы модуля, лимиты совпадают с сервером), пример, правила для промта, превью. Массивы принимаются как `[…]` и как `{ "items": […] }`, до 500 записей.
- Сервер — `ImportService` (main): модули регистрируют обработчик на свой тип в `container.ts`, весь payload сначала валидируется (всё или ничего). Новый тип = запись в `IMPORT_DEFS` + `importer.register(...)`.
- Интерфейс — один `ImportDialog` / `ImportButton` (`components/common/import-dialog`): вкладки «Текст» / «Файл» (.json до 2 МБ), «Скопіювати промт для ШІ», «Вставити приклад», превью или понятная ошибка, «Імпортувати N». Кнопка — `soft` с `FileJson` слева от главной лаймовой. Обратная сторона — `CopyJsonButton` («Копіювати як JSON», тот же формат).

### Просмотр и редактирование записи

- Клик по записи открывает её **для просмотра**; «Редагувати» (или `E`) включает редактирование. Только что созданная запись открывается сразу в редактировании. `InlineTitle` такой записи получает фокус с выделенным названием по умолчанию: «Нова нотатка» перепечатывается сразу.
- **Редактирование — транзакция для пользователя.** В шапке «Скасувати» (`soft`) + «Зберегти» (lime, `data-save`); в просмотре — «Редагувати» (`soft`). Поля по-прежнему автосохраняются (ничего не теряется при сбое), но «Зберегти» подтверждает, «Скасувати» откатывает к снимку, сделанному при «Редагувати» (`RevisionService`), а новую запись удаляет целиком. После отката поля сразу показывают значение сервера — даже текст, напечатанный секунду назад (`resetAllAutosaves` в `use-autosave`). `Esc`, ✕ или клик вне шторки при изменениях спрашивают «Зберегти зміни?» (Не зберігати / Зберегти); без изменений — просто выходят. Если сервер отклонил поле или откат не удался, запись **не закрывается** (`save`/`cancel` возвращают `false`), чтобы введённое не потерялось.
- **Шапка записи** — один порядок везде: закреп/избранное → действия модуля → (пустое место) → корзина → «Редагувати» / «Скасувати»·«Зберегти» → ✕. Это `RecordActions` (`master-detail`); `DetailPane` использует его сам, шторки и страницы записей — тоже.
- `E` включает правку и в шторках (вакансия, карточка доски, отклик): ищется кнопка `data-edit-detail` в верхнем открытом диалоге; при открытом меню, поповере или подтверждении — не срабатывает.
- `SheetContent` при открытии фокусирует саму шторку (без рамки), а не первую кнопку шапки — иначе сразу всплывал её тултип. Поле с `autoFocus` (новая запись) фокус сохраняет.
- Пока запись в правке, лаймовая только «Зберегти»: остальные lime-кнопки записи CSS переводит в soft (один акцент на экран).
- Редактор в `Sheet`: `useModeRef()` + `guardSheet(ref, close)` на `Sheet`/`SheetContent` и `usePublishMode(ref, mode)` внутри редактора — иначе Radix закроет шторку мимо вопроса.
- Реализация — `components/common/detail-mode`: `DetailPane` делает это сам; свои редакторы (sheet, страница) — `useRecordMode(id, type)` + `<RecordMode mode>` вокруг тела + `<EditToggle mode onClose>` в шапке.
- Страница записи со своим редактором (компонент): в `RecordMode` оборачиваются только поля записи. Настройки вида (макет, фон превью) стоят вне него и переключаются в любом режиме — иначе CSS просмотра спрячет невыбранные сегменты.
- Однострочное описание в своём редакторе (добірка): в просмотре — простой текст `text-body` muted (пустое не выводится), в правке — `Field` + `Textarea`.
- Общие поля сами знают режим: `Input`/`Textarea` становятся текстом, `InlineTitle` — заголовком, `MarkdownField` — отрендеренным текстом, `DatePicker` — датой, `TagPicker` — списком меток, `CodeEditor` — read-only; select/toggle/switch показывают только значение (CSS в `globals.css`, вне слоёв). Пустые поля в просмотре скрываются: поле без значения отдаёт `<span data-empty />` (`DatePicker`, `TagPicker`, `NumberInput`, `LinkInput`, `Combobox`, `StarRating`), заполненное — `data-view`; `Field` с пустым `ToggleGroup` или `Select` с плейсхолдером тоже прячется. Числа в просмотре — `fmtNumber` («9 000 000»), ссылка — `link`-кнопка с «…» и полным адресом по наведению, код — высотой по содержимому (без `minHeight`).
- В колонке записи в просмотре нет пустых секций: «Мітки» без меток скрыты, «Зв’язки» без связей — только заголовок и «Зв’язати» (полная подсказка — в его тултипе), в правке — строка «Зв’язок видно з обох записів.». Узкая панель (уже `@2xl` контейнера) ставит колонку под тело.
- Кнопки, которые только меняют запись («+ Етап», «+ Доступ», иконки правки строк), помечаются `data-edit-only` и в просмотре скрыты. Быстрые безопасные действия (копировать, открыть ссылку, таймер, сменить статус в шапке) работают всегда.
- **Checkbox — отметка выполнения** (пункты «Перед відгуком», подзадачи карточки) и кликается в любом режиме — и сам квадрат, и подпись. Настройка записи (вкл/выкл) — только `Switch`: в просмотре он заблокирован вместе со своим `label`.
- **Диалоги, шторки и поповеры — всегда редактируемые формы.** Контекст режима проходит сквозь портал, поэтому `DialogContent`, `AlertDialogContent`, `SheetContent`, `PopoverContent` оборачивают содержимое в `EditableScope` (`detail-mode-context`). Свой редактор внутри шторки ставит `RecordMode` глубже — он перекрывает.

### Пустые записи (черновики)

- Кнопка «+ Створити» создаёт запись с названием из `DRAFT_TITLES` (`shared/entity-types`). Пока её не меняли и поля содержимого пусты (описание типа: `draft` в `EntityDescriptor`), это черновик.
- Повторное «Створити» при живом черновике открывает его же (сервер, `SoftRepository.insert`). Закрытие пустого черновика удаляет его насовсем (`trash.discardDraft`), без корзины; при старте чистятся черновики старше часа.
- Новый тип с кнопкой создания: добавь название в `DRAFT_TITLES` и `draft: { titleField, contentFields }` в дескриптор.

## 9. Пустые состояния и подсказки

- Пустой список внутри карточки — одна фраза `text-body leading-relaxed text-muted-foreground` о том, как список наполнится. Если есть действие — `subtle`-кнопка рядом.
- Пустая секция прямо на фоне страницы (`card`), а не внутри `surface`-карточки: действие — `soft`, не `subtle` (`subtle` = `bg-card`, на card она не читается кнопкой).
- Пустая страница — `EmptyState` (shadcn `Empty`): заголовок `text-lead font-medium`, подсказка, кнопка действия `cta` — всегда `soft`: лаймовая кнопка остаётся одна, в шапке страницы.
- Пустой результат фильтров — один паттерн: заголовок «Нічого не знайдено», подсказка из реально активных условий, `soft` «Скинути фільтри».
- Основная выборка страницы не загрузилась — `LoadError` (`features/route-error.tsx`): `EmptyState` + `TriangleAlert` + лаймовая «Повторити» (шапки нет, акцент один). Пока грузится — `PageSkeleton` того же вида, что `handle.skeleton` маршрута, своих скелетонов не рисовать.
- Неизвестный адрес — `NotFoundPage` внутри оболочки (маршрут `*`): «Такої сторінки немає» + «На головну»; 404 в журнал не пишется.
- Тексты — через скил `design:ux-copy`: глагол в кнопке, без «Нажмите здесь».

## 10. Списки и плитки

- Строка списка — `Item` (`ListItem` в master-detail): заголовок `text-body font-medium`, мета `text-caption`/`text-meta` muted. Активная строка — `ink`.
- Плитка статистики: подпись (`text-body font-medium muted`) → число `text-stat` слева и действие `subtle` справа на одной линии. Ряд итогов без действий — `StatTile` (число `text-headline`).
- Строка «событие с датой»: слева блок даты `w-16 rounded-xl bg-surface` («завтра» `text-meta` + время `text-lead font-semibold`), дальше заголовок и описание, справа бейдж типа. Внутри `surface`-плитки блок даты берёт `bg-card` (`StageDate className`), чтобы не сливаться с ней.
- Длинные списки — только `VirtualList` / `VirtualGrid`.
- Превью markdown-описаний в карточках и строках — через `mdPreview()` (`lib/format`), сырые `**` и `#` на экране недопустимы.

### Чипы и строки списков
- Невыбранный чип (`Toggle`/`ToggleGroup variant="chip"`) — тонировка `foreground/6%`, не `bg-surface`: на карточке-surface он не должен превращаться в обычный текст.
- Ховер строк (`Item variant="muted"`, `ListItem`) и плиток — общий токен `--tile-hover` (surface + 7% foreground). `hover:bg-accent` для кликабельных строк/плиток не использовать.
- Статус записи в строке — `Badge` справа (нейтральный — в очереди, `info` — в процессе, `success` — готово), а не серый текст после точки: серый текст после точки читается как ссылка.
- Двузначный статус отмечает только состояние, которое требует внимания или подтверждает пользу: «Не вирішено» — `destructive`, «Працює» — `success`; противоположное остаётся без отметки. Цветных точек и цветного текста после точки нет.
- Широкий список прячет вторичное через container queries (`@container` на строке, `@md:`/`@lg:`/`@2xl:` на деталях), а не через ширину окна: когда открыта панель записи, список узкий.

### Числа в тексте
- Суммы в плитках-статах — `MoneyValue` / `MoneyLines compact`: от 100 тис. сокращаются («250 тис. USD», «55 млн USD»), точная сумма в подсказке. Полная сумма — в таблицах и тексте, где есть место. Обрезанное «55 000 000,00 US…» — ошибка.
- В бейджах и узких ячейках суммы тоже компактные (`fmtMoneyCompact`, `salaryLabel(…, true)` → «9 млн–10 млн USD»), точная — в `Tooltip`/`title`. Внутри кликабельной строки или карточки (`Item asChild <button>`) — только `fmtMoneyCompact` + `title`: у `MoneyValue` фокусируемый тултип-триггер, а интерактив внутри `<button>` недопустим.
- Проценты — `fmtPercent()` (66,7%), время ответа — `fmtReplyTime()` («за 4 дні», «менш ніж за годину»), счётные слова — `plural()`. «3 відгуків», «66.7%» — ошибки.

### Ряд фильтров
- Ряд собирается `FilterBar` (`components/common/page`): слева чипы (`FilterChips`, переносятся), справа `trailing` — `TagFilter`, затем `SearchInput` шириной `w-72`; второй ряд (`secondary`) — под ними. Поиск всегда справа и одной ширины, `/` находит его в одном месте на любом экране; отдельной большой строки поиска с `autoFocus` нет.
- Длинное имя в чипе (папка, метка) обрезается «…» (`max-w-[24ch]`, полное — по наведению) и не выталкивает соседей на новую строку; метка (`TagChip`) — то же.
- Чипы показывают только значения, где есть записи, плюс выбранное — даже с нулём (`presentChips` в `modules/claude/chips.ts`). Ряд без значений не рендерится: никаких «0»-чипов над `EmptyState`.
- Все контролы в одном ряду фильтров — одной высоты **32px (h-8)**: `FilterChips`/`Toggle variant="chip"` `size="sm"`, `Segmented size="sm"`, `Button size="sm"` (в т.ч. `TagFilter`), `SearchInput` (уже h-8), `SelectTrigger size="sm"`. Поля форм остаются h-9 — это не фильтры.

### Кликабельные плитки
- Карточка, которая что-то открывает (шаблон чек-листа, кейс, дизайн, компонент, сніпет, бібліотека), — утилита `tile`: заметное высветление фона + внутренняя рамка при наведении, внутреннее кольцо при фокусе. `hover:bg-accent` для плиток не использовать — в тёмной теме его не видно. Выбранная (ink) плитка `tile` не получает.
- Карточки одного ряда сетки — одной высоты (`VirtualGrid` растягивает ячейку и карточку), действия прижимаются вниз `mt-auto`.
- Иконка-чип в плитке — светлый скруглённый квадрат (`rounded-xl bg-foreground/[0.07]`), чтобы не путаться с тёмной кнопкой `subtle` рядом.
- Плитка-действие (быстрые действия главной, разделы «Знань») — тот же `Card` + `tile` с иконкой-чипом, клавиатура — `clickableProps`. Чередовать ink/инверсию плиток по индексу нельзя: яркой бывает одна плитка по смыслу, а не каждая вторая.

## 11. Календарь и тепловые карты
- «Сегодня» в месяце и неделе — одним языком: лаймовая рамка клетки/колонки + лаймовая плашка с числом. Инвертированную ink-колонку не использовать: в тёмной теме она слепит.
- Событие — строка агенды: полоска цвета отдельным элементом (не `inset box-shadow` — на скруглении он гнётся полумесяцем), время `text-meta` сверху, название `font-medium`. Цвет текста задаётся явно.
- Сколько событий влезает в клетку месяца, считается по реальной высоте клетки (`useCellCapacity`), остальное — «ще N», выровненное по колонке названий.
- Сегменты `SegmentBar` заполняются только целиком: дробная заливка давала лаймовый «хвостик» в соседнем сегменте.

- Сегодня — залитый лаймовый круг `size-6` с числом (`[text-box:trim-both_cap_alphabetic]` для оптического центра), у ячейки тонкая обводка `ring-lime/70`. Без белых «таблеток».
- В ячейке месяца максимум 3 строки. Если событий больше, последняя строка — «ещё N» (`ghost`-кнопка), она открывает `Popover` со всем днём.
- Сетку месяца переиспользуют: `MonthView` (`modules/calendar/views`) без `onDayClick` — read-only сетка (вид «Календар» доски). Вторую самописную сетку не заводить.
- День чужого месяца — без `opacity`: прозрачный фон, номер и текст событий `text-muted-foreground`. Полупрозрачность роняла контраст названий событий.
- Легенда цветов — простой ряд `text-meta` с точками `ring-1 ring-foreground/20`, не `Badge`: бейдж читается как фильтр. Цвет точки берётся из реального элемента сетки.
- Фолбэк-цвета источников календаря — только `chart-*`; карточкам — `chart-1` (олива), потому что проекты и співбесіди main красит в `#7c8cf8` (≈ `chart-2`).
- Тепловая карта привычек сгруппирована по неделям (зазор между неделями), клетки `h-7 rounded-[5px]`, над картой короткая сводка в мини-плитках, легенда прижата к низу карточки. Значение каждой клетки — в `Tooltip` по наведению; `Tab` останавливается один раз на строку (имя с итогом в `aria-label`), не на каждой клетке.

### Даты и числа

- Даты — только через `lib/format`: `fmtDay` («сьогодні», «завтра», «24 листопада»), `fmtDayFull` («24 листопада», без «сьогодні»; так же `fmtDate` без шаблона и `DatePicker`), `fmtDateTime` («24 листопада о 19:22»), год — только если не текущий. Сокращённые месяцы («лист.») не ставим рядом с запятой.
- «Скільки часу тому» — `fmtRelative`: меньше минуты — «щойно», без счёта секунд.
- Числа в тексте — `fmtNumber` («9 000 000», «4,9»), часы — `fmtHours` («1,5 год»), размеры — `fmtBytes` («5 МБ», «1,5 МБ»): везде десятичная запятая.
- Деньги — `fmtMoney`, числа — `tabular-nums` в колонках и статистике.

### Загрузка и скелетоны

- Скелетон повторяет форму страницы, а не общий шаблон. Виды (`components/common/page-skeleton.tsx`): `list` (шапка, чипы, строки), `grid` (карточки), `board` (колонки), `calendar` (сетка месяца), `dashboard` (главная), `overview` (плитки + карточки обзоров хабов), `form` (настройки, гайд), `detail` (страница записи с колонкой справа), `focus` (тренажёры).
- Вид задаёт маршрут: `handle: { skeleton: '…' }` в `app/router.tsx`; одинаковые страницы делят один вид. Новый маршрут — сразу с `handle`.
- Задержка 150 мс: быстрая загрузка не мигает скелетоном.
- Списки: `VirtualList` / `VirtualGrid` с `loading={list.isLoading}` показывают строки/карточки реального размера; пустое состояние — только после загрузки.

### Графики

- Цвета — только `chart-1…5` (проверены скилом `dataviz`), новые цвета — через его валидатор.
- Подписи осей — компактные числа (`Intl.NumberFormat('uk-UA', { notation: 'compact' })` + валюта: «50 млн $»), ширина оси — под самую длинную подпись, ничего не обрезается. Точные суммы — в тултипе.
- Полосы «доля по категориям», где каждая строка подписана, — один цвет `chart-1`, хвост «Решта категорій» — `muted-foreground`. Цвет по рангу запрещён: цвет следует за сущностью, а не за местом в списке.

## 12. Системные мелочи

- Скроллбар: 8px, почти невидимый в покое, становится заметнее при наведении на область. Цвета — от `foreground` через `color-mix`.
- `overflow-x-auto` всегда в паре с `overflow-y-hidden` (ленты вкладок, полосы превью): иначе браузер включает и вертикальный скролл из-за 1px фокуса/тени.
- Каждая вертикальная область прокрутки резервирует место под скроллбар (`scrollbar-gutter: stable`, задано глобально по классам `overflow-*-auto`): контент не прыгает, когда скролл появляется.
- Сайдбар прокручивается с мягким затуханием сверху и снизу (`mask-image`).
- Кнопки окна (`titleBarOverlay`) следуют теме, которую показывает renderer (`api.app.setWindowTheme`).
- Курсор `pointer` у всего кликабельного (задано глобально в `globals.css`).
- Фокус — `outline 2px var(--ring)` (сплошной, без прозрачности), его не убирать. Действия, скрытые до наведения (`opacity-0 group-hover:opacity-100`), всегда получают и `group-focus-within:opacity-100 focus-visible:opacity-100`: с клавиатуры фокус не попадает на невидимую кнопку (WCAG 2.4.7).
- Диалоги, открытые горячей клавишей (палитра `Ctrl+K`, быстрое добавление), возвращают фокус туда, откуда их открыли: `onCloseAutoFocus={restoreFocus}` (`stores/ui-store`).

## 13. Движение

Анимация объясняет, что изменилось, а не украшает. Одна кривая `--ease-soft` (мягкий ease-out), короткие длительности, ничего не пружинит. Всё отключается системной настройкой «уменьшить движение».

| Что | Как | Где задано |
|---|---|---|
| Переход между страницами | `animate-page`: 240ms, fade + 4px вверх | обёртка `Outlet` в `AppShell` (ключ — путь) |
| Сетка карточек, обзоры | класс `stagger` на контейнере: дети появляются по очереди (шаг 25ms, задержка не больше 8 шагов) | `@utility stagger` в `globals.css` |
| Строки списков | после первой загрузки, нового поиска или фильтра (подпись — первые 12 ключей) — каскад первых 10 строк, шаг 18ms, не больше 8 шагов; при прокрутке без анимации | `VirtualList` / `VirtualGrid` (`useEntering`) |
| Результаты поиска `Ctrl+K` | новые результаты появляются по очереди, оставшиеся не дёргаются | `command-palette.tsx` |
| Панель просмотра справа | `animate-pane`: выезд на 14px + fade | `DetailPane` |
| Раскрытие хабов в сайдбаре | высота `collapsible-down/up` | `sidebar.tsx` |
| Вкладки | содержимое активной вкладки — `animate-page` | `ui/tabs.tsx` |
| Диалоги, поповеры, тултипы | штатные анимации shadcn (`tw-animate-css`) | `components/ui` |

Правила:
- Анимации входа — только `fill-mode: backwards`: после старта элемент свободен, `transform` от dnd-kit, hover и `active:` работают. Поэтому **не ставь `stagger` на сортируемые сетки** (dnd-kit).
- Не анимируй то, что появляется от прокрутки или при каждой перерисовке данных — только реакцию на действие человека.
- Новая анимация — сначала токен `--animate-*` в `@theme`, потом использование.

## 14. Общие компоненты (`components/common`)

Прежде чем писать свой блок, проверь этот список: копия в модуле со временем расходится с оригиналом.

- `IconAction` (`icon-action`) — иконочное действие в строке или тулбаре: `ghost icon-xs`, `label` = `aria-label` + `Tooltip`.
- `FormDialog` (`form-dialog`) — диалог-форма «заголовок → поля → Скасувати / лаймовая отправка»; `invalid` и `pending` блокируют кнопку и Enter, ширина — `className`.
- `StatTile` (`stat-tile`) — плитка итога в ряду (`tone` `surface` / `ink` / `lime`, одна яркая на ряд); `value` — любой узел: строка, `MoneyValue`, `MoneyLines compact` (в финансах — обёртка `MoneyStatTile`).
- `StatCell` (`stat-tile`) — маленькая ячейка «подпись + число» внутри записи с пояснением в `Tooltip` (интервальные повторения слова или вопроса).
- `NumberField` (`number-field`) — подписанное число с диапазоном из `rangesOf`, единица — addon, ошибка «Від … до …» под полем; в диалоге — с `useInvalidFields`. Голый ввод без подписи — `NumberInput`.
- `TextField` / `LinkInput` (`text-field`) — однострочное поле записи с автосохранением; ссылка проверяется `isLikelyUrl`, сохраняется через `normalizeUrl`, кнопка «Відкрити», ошибка скрыта в просмотре.
- `Funnel` / `FunnelTable` (`funnel`) — воронка конверсии (шаги против первого шага) и таблица воронки по группам с колонками-функциями (`WithRate` — «12 · 33,3%»).
- `DropZone` (`drop-zone`) — тело колонки канбана, куда бросают карточки (dnd-kit `id`); `compact` — дорожка в свёрнутой колонке «Закриті».
- `dayKey` (`lib/format`) — ключ дня «2026-01-05» для группировки по дням; свой `format(ts, 'yyyy-MM-dd')` не заводить.

Страница и списки (`page`, `virtual-list`, `master-detail`):
- `PageHeader` / `PageBody` / `Page` — каркас страницы: заголовок `text-title`, действия справа (лаймовая — первой, её жмёт `N`).
- `FilterBar` — ряд фильтров (чипы слева, метка и поиск справа, второй ряд); `FilterChips` — фильтр-чипы (`allLabel`, `count`, `tone`); `SearchInput` — поиск `h-8` с `data-page-search` и очисткой по Esc; `Segmented` — переключатель вида/раздела; `TagFilter` — фильтр по метке.
- `EmptyState` — пустая страница: иконка, заголовок, подсказка, `cta` (soft).
- `VirtualList` / `VirtualGrid` — любые длинные списки и сетки (скелетон, бесконечная подгрузка, каскад появления, равная высота карточек ряда).
- `MasterDetail` + `useOpenParam` — список слева, запись справа, `?open=<id>`; `ListItem` — строка списка (ink, когда выбрана).
- `DetailPane` — панель записи (режим просмотр/правка, шапка, тело, `aside`); `RecordActions` — шапка записи для своих редакторов (шторка, страница); `InlineTitle` — большой заголовок записи; `EntityAside` — колонка «метки, связи, файлы, даты»; `SectionLabel` — подпись секции с действием справа.
- `SegmentBar` — прогресс сегментами («Готово X из Y» рядом); `Kbd` — клавиша в тексте.

Поля (`page`, `text-field`, `number-*`, `date-picker`, `combobox`, `star-rating`, `markdown`, `code`, `tags`):
- `Field` — подпись → контрол → ошибка/подсказка, счётчик после 80%; без `htmlFor` подпись называет группу (`aria-labelledby`).
- `Combobox` — выбор одного значения из списка с поиском (тема, компания, тека, страна), опционально «Створити «…»» и сброс; в просмотре — текст вровень с подписью.
- `StarRating` — оценка 0–5 звёздами; в просмотре — статичные звёзды, 0 скрывает поле.
- `DatePicker` — дата/время (`min`, `invalid`, очистка с тултипом).
- `MarkdownField` — длинный текст в Markdown («Текст»/«Перегляд», в правке открывается на «Текст»); `Markdown` — рендер; `CodeEditor` — код (CodeMirror, лимит, «Форматувати»); `CodeBlock` — подсвеченный код без редактора (превью в карточках).
- `TagPicker` — метки записи; `TagList` / `TagChip` — метки в строках (обрезаются «…»).

Действия и данные (`copy-button`, `confirm`, `import-dialog`, `links-panel`, `attachments`, `money-value`):
- `CopyButton` — копирование (без `label` — иконка с тултипом «Скопіювати»; на коде — `variant="code"`).
- `Confirm` — подтверждение необратимого (destructive, фокус на «Скасувати»).
- `ImportButton` / `ImportDialog` / `CopyJsonButton` — импорт и копирование JSON.
- `LinksPanel` — связи записи; `AttachmentsPanel` — файлы записи: «Додати файл» или перетаскивание, «Відкрити»/«Показати в папці», удаление с диска только через `Confirm` и только в правке.
- `MoneyValue` — сумма в плитке (сокращается, точная в тултипе, не шире плитки); `MoneyLines` — суммы по валютам, `compact` для плиток с обязательной фразой `emptyLabel` вместо «—»; `moneyEntries` (`lib/money`) — ненулевые валюты.
- `clickableProps` (`lib/clickable`) — карточка/строка, которая работает как кнопка: Enter и пробел, клавиши вложенных кнопок до неё не доходят.

Общие блоки вне `components/common`:
- `LoadError` / `NotFoundPage` (`features/route-error.tsx`) — страница, чья основная выборка не загрузилась («Повторити»), и неизвестный адрес («На головну»).
- `SettingsSection` / `SettingsRow` (`features/settings/section.tsx`) — секция настроек (`id` = якорь `/settings#…`) и строка «подпись → контрол». Контрол передаётся функцией `(id) => <Switch id={id} />`, подпись становится `Label htmlFor`: клик по ней переключает, скринридер называет контрол. Подходит и для карточек `modules/dev/settings-cards`.
- `restoreFocus` (`stores/ui-store`) — возврат фокуса после диалога, открытого хоткеем.

Кандидаты в общие (пока живут в модуле; понадобились во втором — переносить сюда, а не копировать): `DisabledHint` и `useNewParam` (`modules/freelance`), `TrashButton` и `EmptyValue` (`modules/crm/parts`), `presentChips` (`modules/claude/chips.ts`).

## 15. Чек-лист нового экрана

1. Есть только одна лаймовая кнопка или плитка.
2. Заголовки карточек — `CardTitle`, ничего серого и мелкого.
3. Размеры шрифта только из ролей (`text-meta…text-display`).
4. Переходы из карточек — `subtle`, ссылки в тексте — `link`, иконки — `ghost` + `Tooltip`.
5. Пустые состояния объясняют, как наполнится экран.
6. Скриншоты в светлой и тёмной теме (`npm run snap`, `SNAP_THEME=dark`), затем скилы `ui-design-review:ui-review` и `design:accessibility-review`.

## 16. Расширение Chrome (попап и настройки)

Попап — тот же продукт, только без shadcn: обычный HTML/CSS в `extension/`.

- Токены в `extension/popup.css` зеркалят `globals.css`: `card` → `--bg`, `surface`, `foreground` → `--fg`, `muted-foreground` → `--muted`, `input`, `ring`, `destructive` → `--danger`, `success`, и роли шрифта `--text-meta…--text-heading`. Меняешь токен в приложении — поменяй и в попапе.
- Попап укладывается в лимит Chrome 600px: прокручивается `body` (`max-height: 600px`, у `html` — `overflow: hidden`), футер с главной кнопкой `sticky`, тень над ним — только когда есть прокрутка (`animation-timeline: scroll()`). Проверка — `node scripts/snap-extension.mjs <dir>`, кадры `*-600.png`.
- Выбор одного значения (куда сохранить, вид закладки, режим скриншота) — сегмент `role="radiogroup"` с приподнятой нейтральной плашкой, как `Segmented` в приложении: одна остановка `Tab`, стрелки выбирают. Лаймовые только логотип, «Зберегти у Vault» и галочка успеха.
- Поля — как `Input` приложения: рамка `--input` + тонировка `foreground` 4%, фокус — рамка `ring` 60% и кольцо 3px `ring` 25%. Ошибка — `.field-error` под полем + `aria-invalid` (рамка `--danger`); ошибка связи — плашка вверху с действием («Відкрити налаштування», «Перевірити знову»).
