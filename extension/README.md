# Vault — розширення для Chrome

Виділили код на GitHub чи Stack Overflow, побачили класний сайт, компонент або бібліотеку — натисніть кнопку, і запис уже у Vault з посиланням на сторінку.

## Встановлення

1. У Vault відкрийте **Налаштування → Розширення для Chrome** і натисніть **Встановити розширення**. Vault оновить папку розширення, скопіює шлях до неї й відкриє в Chrome `chrome://extensions` (якщо Chrome не знайдено — відкрийте сторінку самі).
2. Увімкніть **Режим розробника** (перемикач праворуч угорі) і натисніть **Завантажити розпаковане**.
3. Вставте шлях (**Ctrl+V**) у поле «Папка» й натисніть **Вибрати папку**.
4. Закріпіть іконку Vault на панелі Chrome (значок пазла → шпилька).

Папка розширення — `<дані Vault>/extension` (на Windows `%APPDATA%\Vault\extension`), не папка програми: оновлення Vault її не видаляє. Під час розробки можна завантажити й папку `extension` з репозиторію.

Гаряча клавіша: **Ctrl+Shift+S** (на Mac — **Cmd+Shift+S**). Змінити її можна в `chrome://extensions/shortcuts`.

## Підключення

1. Запустіть Vault (достатньо, щоб він був у треї).
2. Натисніть іконку Vault у браузері → **Під’єднати до Vault**.
3. Vault покаже вікно «Дозволити розширенню доступ до Vault?» з адресою розширення — натисніть **Дозволити**. Розширення отримає ключ саме й напише «Під’єднано».

Попап може закритися, коли з’явиться вікно Vault: у Chrome 127+ він відкриється знову сам, у старіших — натисніть іконку ще раз. Запит діє хвилину; «Відхилити» (або Esc) у Vault — і ключа розширення не отримає.

Запасний спосіб: у Vault **Налаштування → Розширення для Chrome → Ввести ключ вручну**, скопіюйте ключ і порт (за замовчуванням 47219), у розширенні — правий клік по іконці → **Параметри**, вставте їх і натисніть **Зберегти й перевірити**. Порт, якщо змінили його у Vault, теж задається там.

«Відключити» у Vault змінює ключ і від’єднує всі розширення — під’єднайте їх знову.

## Оновлення

Нічого робити не треба. Під час запуску Vault кладе в папку розширення версію, що постачається з ним, а розширення порівнює її зі своєю (`/ping` → `extension`) і, якщо у Vault новіша, перезапускається (`chrome.runtime.reload()`). Перезапуск — не частіше одного разу на версію; чернетки з попапу переживають його. Якщо після перезапуску версія не змінилася (розширення завантажено з іншої папки), попап підкаже встановити його заново.

## Куди зберігається

Цілей вісім, вони стоять двома рядами: зверху код і помилки (**Сніпет**, **Компонент**, **Бібліотека**, **Помилка**), знизу сторінки (**Закладка**, **Нотатка**, **Дизайн**, **Вакансія**). Стрілки ←/→ переходять до сусідньої цілі, ↑/↓ — у другий ряд.

| Ціль | Що створюється у Vault |
| --- | --- |
| **Сніпет** | Сніпет із виділеного коду. Мова визначається сама (підпис «Визначено автоматично»), її можна змінити у списку поруч із полем «Код». Назва — із заголовка сторінки: для файлу на GitHub — «файл · власник/репозиторій», для Stack Overflow — питання без мітки й назви сайту. Посилання на сторінку додається в опис. Без коду не зберігається. |
| **Нотатка** | Нотатка з виділеним текстом і посиланням на сторінку в кінці. |
| **Помилка** | Запис у «Помилках і рішеннях»: виділений текст — текст помилки, «Причина» і «Рішення» — необов’язкові. Назва — із заголовка сторінки (для issue на GitHub — без «Issue #N · власник/репозиторій»). З рішенням запис одразу «Вирішено», без нього — відкритий; посилання на сторінку додається до рішення (або до причини, поки рішення немає). |
| **Дизайн** | Картка в «Дизайнах» зі скриншотом і посиланням на оригінал. Потрібен скриншот. |
| **Закладка** | Закладка «прочитати». Вид (стаття, відео, курс, документація, репозиторій) підказується за сайтом, його можна змінити у формі. Виділений текст потрапляє в нотатки. |
| **Бібліотека** | Для npm і GitHub підставляються назва, посилання й команда встановлення, опис береться з npm (для GitHub — лише якщо пакет посилається на цей репозиторій). Інша сторінка зберігається як документація. Статус «Хочу спробувати». |
| **Компонент** | Компонент зі скриншотом-обкладинкою. Виділений на сторінці код стає кодом компонента. |
| **Вакансія** | Вакансія в статусі «Збережено». Майданчик визначається за адресою (Djinni, DOU, LinkedIn…), виділений текст — опис. |

Ціль підказується автоматично за адресою сторінки (виділений код на gist.github.com, у файлі на GitHub, на Stack Overflow та інших сайтах Stack Exchange — «Сніпет»), а останній вибір запам’ятовується для кожного сайту. Введене у формі не губиться, якщо вікно закрилося (клік повз нього): відкрийте розширення на тій самій вкладці ще раз.

Зберегти: кнопка **Зберегти у Vault**, **Enter** в однорядковому полі або **Ctrl+Enter**. Після збереження вікно підкаже, в якому розділі Vault шукати запис, і запропонує **Відкрити у Vault** (запис відкриється в застосунку) або **Зберегти ще**. Якщо запис збережено без скриншота, галочка стане сірою з поясненням.

## Скриншот

- **Видима область** — те, що зараз на екрані.
- **Виділити область** — вікно закриється, виділіть прямокутник мишею (Esc — скасувати). Вікно відкриється знову зі скриншотом (у старих версіях Chrome на іконці з’явиться «1» — натисніть на неї ще раз).
- **Без скриншота**.

Сніпет, нотатка й помилка зберігаються без скриншота — блоку «Скриншот» у формі для них немає.

Нові цілі (сніпет, нотатка, помилка) потребують Vault із підтримкою розширення 0.2. Якщо Vault старіший, форма попросить його оновити.

На службових сторінках Chrome (`chrome://…`, магазин розширень) скриншот і читання виділеного тексту недоступні: зберігайте без скриншота, а текст вставляйте вручну. Дизайн на такій сторінці не зберегти — виберіть, наприклад, «Закладку».

## Приватність і безпека

Розширення звертається лише до `http://127.0.0.1` — до Vault на цьому комп’ютері. Кожен запит підписано ключем, без нього Vault нічого не приймає. Жодних зовнішніх серверів, аналітики чи віддаленого коду.

Під’єднання без копіювання ключа:

- `POST /pair` створює **один** запит (новий замінює старий), що живе 60 секунд; запитувати можна не частіше разу на секунду й не більше 6 разів за хвилину. Відповідають лише запитам з адрес `chrome-extension://…` / `moz-extension://…` і з `Host: 127.0.0.1:<порт>` — сайт (і сайт, що підмінив DNS на 127.0.0.1) запит не створить.
- Ключ видає лише `POST /pair/<id>` після **Дозволити** у вікні Vault, один раз і лише тому розширенню, що питало. POST, а не GET: на GET до дозволеного хоста Chrome не додає заголовок `Origin`, за яким Vault перевіряє розширення.
- У маніфесті є поле `key` — завдяки йому id розширення сталий у будь-якій папці (`ighcmeieigdefhjpidfbcainaoopopbk`), і Vault позначає його у вікні дозволу як «Розширення Vault»; інший id — «Невідоме розширення». Ключ у маніфесті — лише публічний, приватного в репозиторії немає. Для магазину Chrome поле `key` треба прибрати.
- Vault пам’ятає, яким розширенням дозволено доступ (Налаштування → «Розширення для Chrome»), і ніколи не пише ключ у журнал.
